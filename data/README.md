# Data access and reuse gate

Checked 2026-10-06. The [NASA dataset page](https://data.nasa.gov/dataset/cmapss-jet-engine-simulated-data) lists a `CMAPSSData.zip` resource and describes complete training trajectories and truncated test trajectories. The [ZIP resource page](https://data.nasa.gov/dataset/cmapss-jet-engine-simulated-data/resource/5224bcd1-ad61-490b-93b9-2817288accb8) says **License not specified**. Public access is not a clear grant to redistribute the bytes. The separate [C-MAPSS simulator software page](https://data.nasa.gov/dataset/c-mapss-aircraft-engine-simulator-data) says that software is unavailable; it is a different item.

The user supplied an extracted ZIP locally on 2026-10-06 and confirmed they have permission to reuse NASA data for this work. Its SHA-256 is `74BEF434A34DB25C7BF72E668EA4CD52AFE5F2CF8E44367C55A82BFD91A5A34F`. The ZIP has 14 entries; each extracted file was checked byte-for-byte by SHA-256 against its ZIP entry. This confirms extraction integrity, not that the ZIP bytes match an independent NASA checksum. The included `readme.txt` describes the dataset but contains no public license or general redistribution terms. The project uses the files locally and does not bundle them with derived reports.

To retry locally with network access, run `node scripts/download-nasa.js`. It resolves the resource URL from NASA's CKAN API and saves `data/raw/CMAPSSData.zip`. Inspect the archive and any license/readme before extracting. The loader accepts an extracted `train_FD001.txt` via `loadFd001`.

Verified FD001 schema: whitespace-delimited 26 numeric columns: engine ID, cycle, three operating settings, and 21 sensors. The loader enforces exactly 26 fields, positive integer IDs and cycles, finite values, and contiguous cycles starting at one. The local `train_FD001.txt` has 100 complete engine trajectories, 20,631 rows, and 128–362 cycles per engine. The local `test_FD001.txt` has 100 truncated trajectories and 13,096 rows; `RUL_FD001.txt` has 100 positive labels (7–145). The official test trajectories are used only for a last-snapshot prediction check, never for complete-life policy replay.

The self-authored fixture in `tests/fixtures/toy-lives.json` remains the software verification case. The local FD001 data are used for the separate `outputs/report-fd001.json` evaluation. Both studies simulate interventions; neither measures real maintenance outcomes or aircraft safety.
